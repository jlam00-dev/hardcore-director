# Seedance 2.5 提示词工具

用于 Seedance 2.5 / 即梦 2.5 的 T2V、I2V、多模态参考、编辑和延长任务。以字节跳动官方模型页与发布说明为能力边界；服务商独有参数必须放在提示词之外，并标明服务商。

官方资料：

- https://seed.bytedance.com/en/seedance2_5
- https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5

## 证据与服务商边界（2026-10-01 复核）

- **模型官方事实**：单次最长 30 秒，可延长；单次参考最多 30 张图片、10 段视频、10 段音频。来自上述字节跳动发布说明。
- **服务商第一手页面**：Higgsfield 网页公开展示 1080p、50 个多模态参考及码率选项；这只能证明该服务商的网页入口，不证明即梦或其公开 API 接受同样字段。
- **第三方服务商观察**：OSide 的 `models_explore`/CLI 快照记录了四模式、首尾帧字段和引用计数规则。这里只把它作为待核实的 Higgsfield 路由记录；上游自行标为 `OFFICIAL` 的转录不等于本包已拿到第一手接口证据。
- **实践建议**：素材保真等级、首尾帧文字锚定、无音乐写法等属于创作约定；没有本路线生成测试时，不写“已验证有效”或稳定成功率。

先记录实际使用的服务商和入口（即梦网页 / Higgsfield 网页 / CLI / 公开 API），再交付平台参数。不同入口的字段不能互借。

### Higgsfield 路由差异

| 入口 | 本次可核实的边界 | 交付规则 |
| --- | --- | --- |
| 网页 | 官方模型页宣称 1080p、最多 50 个参考；当前生成界面需要登录，控件未作登录后复核 | 写作网页设置建议，执行前核对当前界面 |
| 公开 Text-to-Video API | 参数表与官方页面内嵌 Input Schema：`duration` 4–30、`resolution` 480p/720p/1080p、`bitrate_mode=standard/high`（默认 high），以及画幅、输出格式和声音开关；schema 不接受额外字段 | 1080p 与码率按此入口 schema 建议；不添入未经此 schema 确认的首尾帧或 CLI 模式字段 |
| CLI/catalog | OSide 2026-09-26 快照记录 480p/720p/1080p、`bitrate_mode=standard/high`，四模式与首尾帧角色 | 标“第三方观察，未在本包执行验证”；只有实际入口 schema 确认后才作为可提交参数 |

官方公开页的可见参数表未展开码率，但内嵌 Input Schema 已列出它。公开 API 的码率默认 high，CLI 快照默认 standard，不能混用入口默认值；执行前仍核对实际入口 schema。不能用营销页面中的 4K 文案覆盖具体参数表。本次复核没有生成请求或服务端参数试验。

仅在 Higgsfield CLI/catalog 路线经当前 schema 确认后，采用以下快照规则：

- `t2v` 不附参考；`omni_reference` 至少附一个参考，首帧或尾帧也计数。
- `start_image` / `end_image` 仅在 `omni_reference`；图片参考加首尾帧不超过 30，全部素材加首尾帧不超过 50。
- `video_edit` 忽略目标 `duration` 与 `aspect_ratio`，按源片长度计费；`video_extension` 继承源画幅，另需 `extension_mode=forward/backward`。
- 快照中的 `generate_audio=false` 表示关闭全部生成音频，不能用它实现“保留对白和音效，仅去 BGM”。

字节跳动官方的 10 段视频/10 段音频数量可作模型上限；组合时长、文件大小等未在本次第一手资料中确认，按实际入口检查，不套用第三方所谓“稳定范围”。

## 先选模式

- **T2V**：文本定义主体、环境、动作、镜头、光影和声音。
- **I2V**：参考图锁定开场与身份，正文只重点说明运动和变化。
- **Reference**：图像管身份/产品/空间，视频管动作/运镜/节奏，音频管音色/台词/节拍。
- **Edit**：先写“保持什么不变”，再写目标对象、影响时段和唯一修改。
- **Extend**：从源视频边界状态开始，只写新动作，不复述已经完成的内容。

## 生成前最少确认项

输入模式、有效时长、连续长镜头还是切镜、素材及各自职责、对白/声音、最终落点。简单动作不要因为模型支持 30 秒就默认用满 30 秒。

## 简单镜头模板

```text
[主体与环境]。[可见的动作起点 → 变化 → 收束]。镜头从[景别/机位/主体位置]开始，在[可见事件]发生时以[一种运镜、方向、速度]移动，到[明确构图]停止。[光线、材质和色彩逻辑]。声音：[环境声、动作声、对白或音乐]。最终停在[主体、道具、镜头和残余运动的准确状态]。保持[关键不变量]；不要出现[与本镜最相关的失败项]。
```

## 长段落/复杂参考模板

```text
生成方式：[连续镜头 / 明确切镜]

素材职责：
@Image1 只定义[身份/产品/空间/首帧]；不要迁移[背景/姿势/文字/光线等]。
@Video1 只定义[动作/运镜/节奏]；不要迁移[人物/服装/场景等]。
@Audio1 只定义[声音身份/台词时序/音乐节拍]。

起始状态：[人物站位、朝向、道具归属、环境状态、机位]

时间线：
[0-X 秒]：[一个主要状态变化及其结果]
[X-Y 秒]：[从上一结果开始的下一变化]
[Y-Z 秒]：[收束动作与稳定落点]

镜头：[每段的构图、运动触发点、路径、停止点、轴线]
连续性：[脸、服装、数量、道具、方向、产品结构、光线]
声音：[对白、环境声、接触声、音乐或明确无音乐]
终止状态：[最终画面和保持时间]
限制：[只列最可能发生且会使素材报废的错误]
```

时间段是节奏预算，不承诺逐帧命中。相邻时间段必须无空档、无重叠，并覆盖外部设置的完整时长。

## 素材映射纪律

- 一条素材一句职责；有泄漏风险时同句写排除项。
- 多视角属于同一主体时明确写“这些图片共同定义同一个人/物体，画面始终只有一个该主体”。
- 素材已有准确动作时只写迁移关系和必要改动，不再逐帧重述动作。
- 每个动作段都从上一段的结果开始，记录左右手、道具归属、开合状态、数量、行进方向和遮挡后的再出现状态。
- 参考音频已经包含要说的话时，不转录、不改写；直接要求指定角色严格对齐该音频，且不生成替代或额外对白。
- 需要明确保真程度时，在职责句追加“完整保留 / 只保留指定部分 / 向指定目标迁移属性 / 只作氛围参考”；这是本 Skill 的制作约定，不是平台枚举。

## 首尾帧与声音

首帧和尾帧分别写成独立职责句，再描述两者之间的可见变化。平台有明确首尾帧字段时放在参数块；没有时使用普通参考图加文字职责。两种写法的边界保持效果未在本包比较，不承诺哪种更稳，也不声称所有服务商都使用 `omni_reference`。

不要把“无音乐”藏在含音乐意图的括号中。需要保留其他声音时写：`声音只包含[对白、环境声、动作声]；无背景音乐、无配乐。` 这是基于上游推断的默认写法，仍需听验；不是模型官方保证。编辑去 BGM 时明确只移除音乐，保留对白、口型、环境声、音效与画面。

## 编辑与延长

**编辑：** `以 @Video1 为唯一时间线母版；完整保留[人物身份、镜头运动、节奏、光线、未编辑区域和声音层]。仅在[时间范围/区域]把[目标]改为[结果]。新目标继承原目标的动作时序、路径、遮挡和出画点。`

**向后延长（forward）：** `新段首帧从 @Video1 的末帧状态连续开始，保持[主体、场景、镜头趋势、速度和声音关系]。不要回放已完成动作。随后[新动作链]，最后停在[新终止状态]。`

**向前补拍（backward）：** `生成发生在 @Video1 之前的[动作链]。新段末帧准确落在 @Video1 的首帧状态：[人物姿态、道具位置、机位、光线与运动方向]。属于源片后续的角色和道具不要提前出现。`

## 提交门禁

- 每个参考有职责和排除项；
- 每段只有一个主要变化并有终止状态；
- 动作先写接触/原因，再写运动/反应；
- 镜头有主体、触发点、路径和停止点；
- 时长、画幅、分辨率等参数与提示词正文分开；
- 参数块标明服务商、入口和证据等级；素材计数包括平台首尾帧；
- 不把时间戳表述成逐帧保证；
- 不在一次生成里同时要求两个互相争夺注意力的主要任务。
