# 导演调度、表演与镜头覆盖

在故事和当前剧本成立后，把作者意图转成可以拍摄或生成的空间、行为与镜头。输入是当前节拍和已确认限制；输出交给分镜与平台提示词，不执行媒体生成或自动剪辑。

## 接哪一棒

先读 [共享创作协作合同](creative-collaboration.md) 和当前 `project`、`script`。必要时消费 [剧本诊断](screenplay-diagnosis.md) 的已采用修订。人物外观与造型继续由 [角色设计](../character-design.md) 负责，本模块不另造一张角色 DNA 表。

每场明确观众应该看见、暂时不知道、最后重新理解什么。把“压迫”“疏离”等意图落到可观察的变化，例如出口从谁控制变成谁控制；有意保持同一观看位置也可成立，不为变化而切镜。单一 `project`的画幅、帧率、片长、锁定状态与 `sound_policy`共同约束本阶段；不得另定一套规格或为渲染情绪增加被禁止的音乐、未登记的对白和旁白。

普通场景直接选择合适方案。只有观看位置、知情时机或表演归属真正改变体验时，才比较不同方案；不固定三方案、九宫格或镜头比例。未采用的方案不能混进正式分镜。

## 先调度，再放摄影机

1. 用门、桌、窗等已存在锚点交代人物关系、距离、朝向、退路和谁持有物件。缺少必要空间信息时，标出假设或未决，不凭空增建场景。
2. 按节拍确定谁发起动作、谁保持、谁回应，以及动作结束时关系怎样变化。距离、手势和视线只精确到能改变本次决定的程度，不用数字制造虚假可靠性。
3. 再决定摄影机怎样让观众读懂这个变化。固定机位同样需要目的；用户已锁定机位、单镜头或视角时，围绕限制设计调度。
4. 声明工作侧与轴线，逐镜推导画面左右、出入口方向和视线。需要换侧时用可读的空间重建方式，并说明选择。
5. 光源位置属于场景空间；反打后的画面左右由机位推导。不能把“同一盏窗光”误写成所有机位都“画左来光”。

## 共享输出怎么写

形成 `direction.shots`，每行沿用本次选定的稳定 `shot_id`，绑定真实 `scene_id` 与 `beat_ids`。同一镜可以承载多个成立节拍，但必须放得下；不把“一个主要动作”当作无条件禁止连贯动作的模型规范。

| 合同字段 | 写入的决定 | 谁继续使用 |
| --- | --- | --- |
| `blocking.start` | 人、物、空间的起始关系 | 分镜起点与首帧 |
| `blocking.action` | 主动作、方向、回应及过程 | 分镜动作和视频运动 |
| `blocking.end` | 可冻结、可衔接的终点 | 尾帧及下一镜入口 |
| `blocking.eyelines` | 谁看谁、看什么、何时改变 | 构图、反打与表演 |
| `blocking.prop_changes` | 所有权、哪只手、开合等变化 | 道具连续性与状态检查 |
| `blocking.holds` | 不应随主动作漂移的人或物 | 同镜保持项 |
| `camera_intent` | 观看对象、机位/运动及其叙事理由 | 正式分镜机位与运镜 |
| `performance` | 说前、说中、说后的可见/可听行为 | 分镜、视频提示词和声音单 |
| `coverage` | 该镜承担哪些信息、反应或空间职责 | 节拍落实与剪接判断 |
| `start_state`、`end_state` | 非空平面状态表，表达持续事实与变化 | 分镜端点逐值继承 |

`blocking`六项及`coverage`都是简短字符串；`performance.before`、`during`、`after`也是字符串，不在方法层另建一套嵌套Schema。无变化时说明保持什么，不用空白掩盖缺决定。

`project.locked_state`只放贯穿当前范围不应改变的事实。剧情需要移交的道具持有人、湿污变化、门开关等放到逐镜状态，不把它们错误地锁为全片常量。分镜的起止状态必须与对应导演行一致；跨镜有时间跳跃或有意省略时，声明依据和过渡，不能借“剪掉了”让道具瞬移。

## 表演层：从潜台词到时间顺序

需要情绪表演时才使用，不能为无人物镜头强加反应：

- 先找一个当前动机：试探、遮掩、挽留、拒绝或别的具体意图。
- 用最少的视线、呼吸、面部、身体或声音信号让它可读，按说前、说中、说后排序；静止和不流泪同样有效。
- 既定站位和视线优先。表演不能擅自变成看镜头、加一步、碰新道具或改服装。
- 对白真本仍在 `script.beats[].dialogue`。在表演字符串中按对白 ID说明说法，不另写一个改字版本；下游通过 `line_id`、`speaker`、`text` 传递逐字原文。

自创例：同一句已锁对白“钥匙在桌上。”，可以在说前短暂看向门、说中平稳交代、说后把视线留在对方身上，表达“我希望你留下”；也可以说前继续收拾、说中不抬头、说后停止手上动作，表达“我装作不在意”。两种只是候选，必须与原场景、动作预算和视线限制相容，不凭情绪标签自动采用。

## 镜头覆盖与连续性

先确保剧情需要观众读到的动作、对白、反应和信息都有承载，再决定主镜、近景、插入或画外处理。每次切镜说明增加或改变了什么；不为了凑景别重复同一事件。

将身份/物件识别事实与暂态分开。角色参考图能约束已有身份，不代表可任意重写脸；不得为了凑固定词数或“唯一标记”给用户角色新增痣、伤疤、年龄或族裔。连续性看具体事实，不保证相同seed或一句“不变”就会稳定。

交接、接触、复杂转身或多人移动难以表达时，可提出拆镜、遮挡、反应镜或首尾帧方案；这些是制作选择，不是所有模型的固定禁令。只改变当前失败的控制层，保持未受影响镜头的 ID 与已采用事实。

交给 [分镜交付包](storyboard-package.md) 和 [分镜门禁](storyboard-quality-gates.md) 后，由它们把导演行投影成可执行分镜、首尾帧、参考职责与连续性检查，再交 [模型路由器](../prompt-tools/model-router.md) 选择一个平台方言。模型真实能力和参数由该平台适配器负责，不从本模块的经验中猜字段。

## 不成立时退到哪里

- 镜头没有可说明的故事职责：回到对应 `script`节拍，不用加运镜掩盖。
- 几何、视线或物件接触无法成立：改当前导演调度，再刷新依赖它的分镜。
- 身份、地点或道具事实缺失：交角色/视觉设定负责人，不在提示词里私自补齐。
- 缺实际参考图片：可以继续准备文字与挂图计划；生产必须等待可核实的真实文件和上传授权。
- 平台不支持实现方式：保留导演母版，交适配器提出可行替代，由作者决定涉及表达的取舍。
- 改动 `script`或`direction`后：下游摘要必须重新核对，不把旧分镜、声音、提示词和剪辑单继续当有效版本。`direction.source_hash`由共享校验器给出当前期望值，不能猜填，也不表示作者审批或生成授权。

方法输出与机器检查不能代替表演、口型、空间连续性及声音的实际看验。纯文本可以结构通过并导出草稿 Plan，但没有真实媒体时 `render_ready`仍为 false，媒体与审美、听验不能被写成已通过；没看过成片，不下成片通过结论。
