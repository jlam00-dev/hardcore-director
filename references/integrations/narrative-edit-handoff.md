# 叙事EDL交接

用于已经有锁定剧本和多镜分镜、需要把素材选择及声音交给后期的项目。它先保证“剪辑承接了什么”，再交给 [既有剪辑模块](../video-editing.md)、[Remotion路径](remotion-production.md) 或用户选定的剪辑工具。它不替代现有Engine合成器，也不自动决定剪法。

共享字段与检查以 [创作协作合同](creative-collaboration.md) 为准。

## 从上游取得什么

1. `script.beats`：动作、原因、结果、顺序和对白原文；揭示不能先于它所依赖的信息。
2. `direction.shots` 与 `storyboard.board.shots`：每镜功能、画幅/FPS、计划帧区间、空间与起止状态。
3. `audio.cues` 与 `prompts`：哪些声音由模型生成，哪些留给后期；实际台词和声音短句怎样进入唯一目标平台提示词。
4. 若已有素材：用户获选的take、来源hash、可用入出点、末态和残留疑问。容器可读不等于动作、身份、表演或声音已接受。

## 写出什么

写入 `editorial={source_hash,status,events}`。每个event按已锁镜序包含 `shot_id/beat_ids/start_frame/end_frame/take/cue_ids/notes`：

- 分镜的镜头与节拍必须全部有归属，不能漏镜、加镜或用改名复用旧镜。
- `cue_ids` 消费本镜覆盖的后期cue；跨镜环境床或L/J-cut意图保留同一cue ID与全局锚点，不静默截短。
- 尚无真实素材时，`status=planned`、`take=null`；时间只表示计划预算，不是源片入出点。
- 调用方报告素材窗口时，可登记 `take={asset_id,in_frame,out_frame,fps}`，并关联provided素材的路径与hash；本工具不读取它，因此仍待真实媒体核验，不能声称可渲染。
- `notes` 交代剪辑的叙事理由、尚缺证据与交付下一步。J/L-cut、转场、裁切、叠层或混音提议必须留在后期方案；不能把它们冒充模型生成参数或现有Engine已经执行的动作。

一个镜头的起止状态改变，会影响下一镜的连续性；一个声音cue移动，会影响它所属节拍、对白窗口和后期锚点。修改时更新上游决定，重审受影响下游，输出新版本，保留已接受的原稿和素材。

## 失败怎样退回

| 失败 | 退回 |
| --- | --- |
| 缺必要节拍、反应早于原因、对白意义不通 | 编剧与导演 |
| 镜序、起止状态或空间轴不成立 | 导演与分镜 |
| take没有可用窗口、角色或道具漂移 | 素材审阅，必要时再改参考/提示词；不自动重生成 |
| 切口咬字、声音同步点不明、cue超出其窗口 | 声音交接；先测量和听验，不自动变速或补静音 |
| 素材时长不足或规格不兼容 | 明确提出处理选项；后续规格统一仍走原来的单独审批 |

`creative_handoff.py` 检查的是计划依赖和结构；最后的真实剪辑路径还须核对素材窗口、语音边界、音画、字幕及成片播放。没有来源文件和听验时，给出待测清单，不能靠分数或文件名认定已交付。
