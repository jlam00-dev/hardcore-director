# 分镜交付包与连续性门禁

本模块吸收 Agentara `video-storyboard` 的场次编号、时间核算、素材复用和连续性检查思想，但不把固定九宫格当作默认答案。

rc.7另参考 [zenstory-ai/drama-skills](https://github.com/zenstory-ai/drama-skills/tree/d8a9a9b5f5fa0e46dc2644d55879d1c984ff70e6/skills/short-drama-storyboard) 的场次来源、逐镜首尾状态、关键帧与视觉Bible交接方法。原模块为MIT，版权及完整许可见 [drama-skills-MIT.md](../support/licenses/drama-skills-MIT.md)。以下为本包原创适配，不使用其目录结构、默认语言或平台固定槽位。

实际素材的“通过/失败/未核实”与可用窗口交接另参考 [video-take-review](https://github.com/konradre/video-production-skills/tree/cd92701fd52fbfa668f2247687b32d0f85506fda/skills/video-take-review) 的证据分层，采用 [MIT许可](../support/licenses/video-production-skills-MIT.md) 下的方法概念，不复制其执行工具或项目阈值。

## 从剧本和导演处理中接收

完整项目使用 [创作协作链](creative-collaboration.md) 的同一项目包。先读已锁剧本的scene/beat ID，再读 [导演调度](director-blocking-coverage.md) 的站位、行动、视线、表演和镜头覆盖，随后形成分镜。每镜须说明观众在此刻能看见什么、尚不知道什么，以及这一镜新增的信息；不能为了凑景别重复同一动作。

脚本动机和因果不成立时退回编剧；几何或行动不可能时退回导演；不要让分镜或模型提示词临时补出新的剧情事实。拆镜时保留来源节拍及未受影响镜号，新增子节拍须先回写脚本台账，不把同一动作完整重演两次。

画幅、FPS和总帧数只从项目主表读取。分镜、图片构图、提示词和剪辑交接不得分别另填一套规格；机器门禁使用项目规格作为外部预期，避免多份文件共同写错却内部自洽。

## 交付形态

- 默认：每个镜头一张独立图片，加一份镜头表。独立图片更适合后续图生视频、局部返工和素材引用。
- 用户明确要提案板/联系表时：再生成或排版一张总览板。
- 用户明确要求一张多宫格直接作为平台参考时：才使用单张网格，并写清每格作用。
- 分镜画面必须由图像生成模型或用户素材产生；程序化排版只能整理已经生成的画面，不能替代画面创作。

## 文件约定

```text
storyboard/
  scene-01/
    shot-01.png
    shot-02.png
    manifest.md
```

存在同名文件时不覆盖；只有用户明确要求替换时才覆盖，否则使用 `-v2`。

## 每镜字段

| 字段 | 要求 |
| --- | --- |
| 镜号/时间 | 起止时间连续，总和等于场次时长 |
| 叙事功能 | 这一镜让观众知道、感到或期待什么 |
| 构图 | 画幅、景别、机位、主体位置、前中后景 |
| Blocking | 人物站位、朝向、视线、动作方向、距离 |
| 状态变化 | 起始状态 → 可见动作 → 终止状态 |
| 连续性 | 人脸、服装、伤痕、道具、数量、光线、天气、空间地理 |
| 声音 | 对白、环境声、动作声、音乐和声音桥 |
| 生成用途 | 首帧、尾帧、身份参考、动作参考或风格参考 |

## 连续性台账

建立一个只记录可验证事实的台账：

- 人物：脸、发型、体型、服装、鞋、配件、妆容、伤痕；
- 道具：归属、左右手、朝向、开合、损坏、液位、数量；
- 空间：门窗、道路、关键标志、人物相对位置、轴线；
- 环境：时间、天气、主光方向、色温、雾/雨/烟状态；
- 动作：进入方向、退出方向、受力点、落点、镜尾姿势。

后一个镜头必须从前一个镜头的终止状态开始，除非剧本明确发生时空跳转。

区分全片不变量与剧情暂态。衣着和用户锁定的身份不能随镜改变；道具归属、开合和站位则由明确动作改变并传给下一镜。光源、门窗和人物位置先按世界空间记录，再由当前机位派生画面左/右，不能把“永远在镜头左边”当作真实空间恒定。

## 关键帧与参考素材

首帧只冻结动作开始前的可见状态，动作过程交给视频提示词；需要尾帧时再冻结明确终态。不要把先后发生的多项动作同时画在一张首帧里。画内可见人物、地点和道具逐项对应既有角色/场景/道具资料。

真实参考与挂图计划分别记录：真实参考须来自用户本次提供或本项目获准素材，有明确文件/版本及职责；仅计划制作的角色图或场景图标为待制作。没有真实参考时可继续写方案，但不能编造路径或当作已可上传的生产素材。由图生视频使用哪张首帧、尾帧或身份图，仍由目标平台的当前能力合同决定。

## 画面生成前

1. 核对用户本次提供或本项目已批准的角色图、产品图、场景图和前序分镜，不扩大到其他项目或私人文件；
2. 有视觉参考就传给图像生成模型，不只依赖文字；
3. 先锁定画幅、人物、文案、风格、视觉锚点和终止状态；
4. 每轮只改一个变量；
5. 文字、标志或 UI 必须准确时，优先留出后期叠加位置，不让图像模型临场拼字。

## 质量门禁

- 每张图对应一个清晰镜头，不用近似重复画面凑数；
- 镜头变化推进动作、信息或视点，同时不破坏连续性；
- 文件数量、画幅、编号和用户要求一致；
- 镜头时长总和精确等于场次时长；
- 角色、服装、道具和空间变化都有剧情依据；
- 输出后逐张检查，而不是只检查总览图；
- 分镜图与提示词中的镜号、动作、时间和素材职责一致。

实际生成后，将每镜验收分为通过、失败和未核实：记录原文件哈希、已观察的画面、可用时间窗及真实终态；没有看图、播放或听音的项目保持未核实。通过的素材窗口与终态交给 [叙事剪辑交接](narrative-edit-handoff.md)，声音cue交给 [声音交接](audio-cue-handoff.md)。缺少实测窗口时只能给计划，不能声称成片或EDL已验收。

## 多镜头机器台账

有多镜头、批量生成或精确时间线要求时，按 [分镜机器门禁](storyboard-quality-gates.md) 同时交付 `storyboard.json`。运行包内 `scripts/validate_storyboard.py` 检查整数帧时长、叙事节拍归属、引用映射、首尾状态声明和对白预算。该检查证明声明一致，不能替代实际图像、录音与成片验收。
