# 剧本诊断与最小改稿

用于已有梗概、场景或剧本的检查与修改：人物为什么做这件事、冲突有没有推进、转折是否挣得、信息是否只能靠解释传达。先由本包编剧主模块完成当前稿，再在进入导演处理前使用本模块；只要创意或一段最终文案时，不强制增加审稿流程。

本模块只处理创作文本，不调用生成服务，不改变预算、账号、素材上传或发布授权。评分不能证明实际画面或成片质量。

## 输入与归属

读取用户指定的当前稿及相关已确认限制。明确本轮读到的范围；不能用局部段落替整部作品下结论。

- 作者锁定项：核心事件、结局、逐字对白、人物身份、时代、禁止项，以及明确采用的参考职责。
- 当前创作目标：受众、体量、平台、情绪体验、可用人物/场景和制作限制；已有信息直接沿用。
- 剧本事实：人物当下目标、对抗或阻力、可见行动、观众知道什么，以及变化发生在哪里。

与 [共享创作协作合同](creative-collaboration.md) 连用时，消费 `script.screenplay`、`script.shooting_script` 和 `script.beats`。场景由 `beat.scene_id` 标识；节拍用 `beat.id`；对白来自 `beat.dialogue` 的 `id`、`speaker`、`text`。不另建一份人物事实或对白真本，不为填表发明已经存在的场景 ID。沿用单一 `project`的画幅、帧率、时长、锁定状态与 `sound_policy`；音乐为 `forbidden`时不能以情绪需要为由补配乐，`dialogue: script_only`时不加未登记的台词或旁白。

## 诊断顺序

### 1. 先说清这场在做什么

用当前稿回答：谁此刻想得到什么，什么使它困难，他采取了什么行动，结果给下一步制造了什么条件。把答案绑定真实场景和节拍，区分原文证据与推断。

生活流、抒情片、纪录表达与非叙事任务可以靠观察、关系层次或观众理解的改变成立；不强迫每场翻转正负价值，不把高潮、反派或正向成长作为所有作品的必填项。

### 2. 找到阻断理解或制作的最早原因

按依赖顺序检查，先修上游，不用漂亮台词掩盖结构问题：

| 检查 | 能观察到的问题 | 修改回到哪里 |
| --- | --- | --- |
| 人物选择 | 关键行为缺少前因，人物只为情节点突然变性格 | 人物目标、关系或前置节拍 |
| 行动与反应 | 换几句话重复同一策略，对方反应不影响下一步 | 当前场景的行动链 |
| 转折与信息 | 决定靠临时新人物、巧合或未经铺垫的信息完成 | 前提、伏笔或转折所在节拍 |
| 可见性 | 只有“意识到”“感到”，没有可演的动作、关系或声音承担 | 对应动作或对白 |
| 场景必要性 | 删掉后没有丢失有用信息、体验或节奏作用 | 场景目的及相邻场次连接 |
| 时间与资源 | 对白、停顿、行动挤不进片长，依赖未提供的演员或地点 | 体量与实现方案 |

把“缺乏电影感”“有 AI 味”等判断落成证据：哪一句重复了什么，哪一次选择缺了哪条原因，哪项信息观众尚未获得。没有证据的喜好只能列为可选意见。

### 3. 提出最小可行修订

每个问题交付：位置、必要短引文或事实冲突、观众/制作影响、建议改动、负责的上游。允许“不改”，但说明这个选择如何服务作者目标。

优先改变一个动作的条件、一次反应、信息落点或进出场位置；需要大改主线时先展示取舍。作者锁定项与问题冲突时，明确卡点，请作者决定，而不是默默改结局、补新人物、替换身份或重写锁定对白。

自创小例：修伞人一边说“已经修好了”，一边把仍漏水的伞递给顾客；顾客再说一次“不好用”。两句都没有改变局面。若作者已经锁定“最后不收钱”，可建议让顾客把伞重新举过修伞人头顶，漏水落到他的账本上，迫使他选择；是否采用交回作者。这个动作必须适合既有场景与人物，不能成为每个故事的套路。

### 4. 修订后再检查因果和锁定项

- 新动作是否有原稿或明确采用的新决定支撑；没有把解释挪成另一段解释。
- 前后节拍的 `cause`、`action`、`effect` 能接起来；开场可以承接已经声明的初始条件，不必强造前一镜。
- 未受影响的场景、节拍和对白 ID 保持；拆分、合并或改变职责时写清替代关系。
- 锁定对白逐字保留，含标点；对白的 `speaker` 不换人。行为可以提供潜台词，不能借表演提示偷偷添字。
- 修订没有增加未经采用的地点、人物、道具、声音或平台能力。
- 时长估算是制作预算，不承诺生成模型逐帧命中；实际表达仍需小样或成片看验。

## 交付和下一位消费者

用户只要诊断时，交问题与最小修订建议，到此结束。用户要求继续制作时，把已采用的修订交回当前编剧主模块，更新同一份 `script`；再由 [导演调度与镜头覆盖](director-blocking-coverage.md) 消费当前节拍，形成可见空间与镜头决策。

共享合同不增加 `diagnosis` 等第二套机器字段；诊断可以是普通文字记录。`source_hash` 由共享校验器对真实上游给出，不能猜填或把旧摘要当新版本证明。改变剧本后，既有 `direction`、`storyboard`、`audio`、`prompts`、`editorial` 都需重新核对依赖；保留旧文件供比较，不把它们伪装为仍然有效。

共享校验结果的 `issues`按 `stage`、`code`、`message`、`return_to`定位责任；先处理最早不成立的上游，受影响下游标为过期或受阻，不伪造已通过状态。若问题只在模型方言、参考绑定或输出规格，交回平台适配器；不要为了迁就一个错误参数重写已成立的剧情。
